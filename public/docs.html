POST GET /api/speedtest New in v0.3.0
Open Live Output ↗
Performs an on-demand network speed test against the nearest Cloudflare Edge. Measures download throughput (Mbps), upload throughput (Mbps), latency (ping), and jitter in ~1.5s without external dependencies. 
# Run on-demand test:
curl -X POST http://localhost:3000/api/speedtest

# Retrieve last cached result:
curl -s http://localhost:3000/api/speedtest

GET /api/devices Enhanced in v0.4.0
Open Live Output ↗
Returns list of all active network nodes on the local subnet (/24) including IP, MAC address, manufacturer from IEEE OUI database, friendly name (SSDP/UPnP), connection medium (Wi-Fi vs Wired), ping RTT, and automatic device classification. Each device carries a deviceClass (phone, laptop, tv, iot, router, server, or unknown) plus macRandomized and a human-readable classReason. Classification layers, in priority order: seeded device registry → mDNS hostname patterns (iPhone/Pixel/Galaxy/…) → MAC randomization detection (locally administered MACs are the iOS/Android Wi-Fi privacy default — a strong phone signal) → IEEE OUI vendor signature (Intel/Qualcomm Atheros → laptop; Espressif/Tuya/Xiaomi → IoT; Apple → SSH tiebreak) → SSH port 22 probing. The response also includes deviceClassCounts, e.g. {"phone": 1, "laptop": 1}. 
curl -s http://localhost:3000/api/devices

GET /api/shelly New in v0.5.0
Open Live Output ↗
Full state of the local Shelly Presence Gen4 mmWave sensor, bridged by Grima: device identity (model, MAC, firmware), online status, live occupancy (present, numObjects), ambient illuminance (dark/bright), monitored zone config, and a recent event log. Data arrives via 5s RPC polling plus a persistent WebSocket event channel to the device for real-time transitions. 
curl -s http://localhost:3000/api/shelly

GET /api/events/stream New in v0.6.0
Open Live Stream ↗
Live SSE event stream combining all Grima sources in real time:
  • source: "shelly" — presence_detected / presence_cleared, illuminance_changed, device_online/offline from the Shelly mmWave sensor.
  • source: "network" — device_connected / device_disconnected transitions detected between router ARP scans (debounced over ~30s of consecutive empty sweeps).
Sends an initial stream_connected snapshot (current presence state + last 20 events) on connect, then pushes frames as event: <type> + JSON data. Heartbeat comment every 25s. 
# Live stream (Node 18+ / any SSE client):
curl -N http://localhost:3000/api/events/stream

// Browser JS:
const es = new EventSource('/api/events/stream');
es.addEventListener('presence_detected', e => console.log(JSON.parse(e.data)));
